## Frontend Entrypoints

- **Dev server:** `npm run dev` → Vite dev server on http://localhost:5173
  - Hot reload enabled
  - Proxies API calls to http://localhost:5000 (configured in package.json)

- **Production build:** `npm run build`
  - TypeScript compilation (`tsc -b`)
  - Vite bundling → `dist/`
  - Ready for static hosting or reverse proxy

- **Preview:** `npm run preview`
  - Local preview of production build (useful before deploy)

## Backend Entrypoints

- **Development Flask server:**
  ```bash
  cd flaskapi
  uv run python -m flask --app src.mmux_flaskapi run --port 5000
  ```
  - Watches for changes (reload enabled in dev mode)
  - Blueprint modules auto-discovered from `src/mmux_flaskapi/blueprints/`

- **Production (Gunicorn):**
  ```bash
  gunicorn 'src.mmux_flaskapi:create_app()'
  ```
  - Recommended for production deployments
  - Configured in pyproject.toml via gunicorn dependency

- **Tests:**
  ```bash
  uv run pytest
  ```
  - Runs all tests with coverage report → `htmlcov/index.html`

## Key Application Modules

### Backend Blueprints (src/mmux_flaskapi/blueprints/)
- **dakota.py** — (Likely) Dakota integration for sensitivity/uncertainty analysis
- **sampling.py** — LHS sampling, design of experiments
- Others — Modular API endpoints (check actual files for full list)

### Frontend Key Components
- **Job management:** Job selector, job table
- **Sampling UI:** Parameter distribution editor, LHS design interface
- **Results visualization:** Plotly-based graphs, results export
- **Navigation:** Router setup (check src/App.tsx for routes)

## Workspace Dependencies (uv)

- **mmux_python** — Local Python library (workspace member in pyproject.toml)
  - Path: `flaskapi/mmux_python/`
  - Imported as `mmux_python` or `mmux-python`

## Build & Deployment Artifacts

- **Frontend:** `node/dist/` (after `npm run build`)
- **Backend:** No build artifact; runs from source via Flask/Gunicorn
- **Tests:** Coverage reports → `flaskapi/htmlcov/`, XML → `flaskapi/coverage.xml`
- **CI/CD:** GitHub Actions workflows in `.github/workflows/`
